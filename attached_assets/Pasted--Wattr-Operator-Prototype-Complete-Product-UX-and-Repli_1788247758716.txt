# Wattr Operator Prototype — Complete Product, UX and Replit Build Specification

## Mission

Refactor and extend the existing Wattr prototype into an operator-grade decision cockpit for AI/HPC data-center thermal operations.

This is NOT a generic DCIM dashboard.

Wattr should make the relationship between compute activity and physical infrastructure understandable.

The central operating workflow is:

IT WORKLOAD CHANGE
→ PHYSICAL HEAT GENERATION
→ THERMAL PROPAGATION
→ COOLING RESPONSE
→ FUTURE THERMAL STATE
→ WATTR RECOMMENDATION
→ SAFETY VALIDATION
→ EXPECTED OUTCOME
→ HUMAN DECISION
→ AUDIT HISTORY

The product must make this chain visually understandable.

The prototype currently has no calibrated customer digital twin.

Therefore:

DO NOT claim that the synthetic facility model is an accurate digital twin of a real customer facility.

Build a deterministic SYNTHETIC FACILITY MODEL / DEMO TWIN that demonstrates how Wattr would operate if connected to real telemetry and a calibrated physics model.

The product architecture must allow the synthetic model to be replaced later by:

- customer topology
- BMS/DCIM telemetry
- historian data
- CFD models
- Modelica/FMUs
- reduced-order physical models
- live workload telemetry

without redesigning the operator experience.

# 13. PRIMARY DEMO SCENARIO

Build one excellent deterministic scenario.

GPU Cluster B begins a large training run.

The workload scheduler indicates a future load increase.

Rack electrical power begins increasing.

Heat generation rises.

CDU-03 responds with physical lag.

Traditional reactive cooling is late.

Wattr detects the upstream workload/power signal.

Wattr predicts thermal margin degradation before the temperature limit is reached.

Affected racks become highlighted.

An incident is generated.

The Thermal Dependency Graph highlights:

GPU Cluster B
→ racks
→ loop
→ CDU-03

Wattr proposes a pre-emptive adjustment.

The Safety Shield validates it.

The operator compares:

BASELINE

vs

WATTR RECOMMENDATION

The operator simulates the recommendation.

Risk is reduced in the synthetic scenario.

The operator marks the recommendation reviewed.

The decision enters the audit log.

Every screen must derive from the same scenario state.

# 15. SIMPLE PHYSICS ENGINE

The synthetic twin should not use random-number animation.

Build a deterministic reduced-order thermal simulator.

Conceptually:

workload
→ electrical power
→ heat generation

heat generation
+ neighboring thermal coupling
+ thermal mass
− cooling removal
= temperature evolution

Cooling response should contain realistic lag.

Each rack can contain state such as:

power
temperature
thermal mass
cooling effectiveness
neighbor coupling

Cooling equipment can contain:

capacity
flow
setpoint
response lag
availability
efficiency

The model does NOT need CFD fidelity.

It needs internal consistency.

Changing:

rack power

CDU flow

cooling setpoint

ambient temperature

must create sensible downstream effects.

Label resulting metrics:

SIMULATED

unless they come from real data.

# 56. DEFINITION OF DONE

A new data-center operator should be able to enter Wattr and determine:

which facility needs attention

what is happening

where it is happening

what caused it

what is likely to happen next

how heat/cooling dependencies are connected

what Wattr recommends

why Wattr recommends it

what happens if they do nothing

without requiring a Wattr founder to explain the application.

why

and where to drill down.

A commissioning/model user should be able to understand:

how the facility representation is constructed

how assets and telemetry are mapped

and what constraints govern recommendations.

The application should demonstrate Wattr's central product thesis:

COMPUTE LOAD IS NOT SEPARATE FROM PHYSICAL INFRASTRUCTURE.

Wattr connects workload intent to physical thermal behavior early enough for facility teams to understand risk, simulate alternatives and make safer cooling decisions.

The digital twin is the spatial interface.

The Thermal Dependency Graph is the causal/topological interface.

The timeline is the temporal interface.

The Trust Cockpit is the decision interface.

The Safety Shield is the trust interface.

Ask Wattr is the natural-language interface.

The underlying physical-AI/controller layer—potentially including SNN/RL models—is the intelligence that connects them.
